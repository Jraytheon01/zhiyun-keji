# 通用录音内容生成提示词

日常只修改以下三个变量：

- `场景`：例如“初三学生和老师一对一补习一元二次函数”。
- `录音时长`：例如“20 分钟”。
- `说话人数`：例如“2 人”。

```text
请生成一份用于录音转写系统联调的虚构录音数据。

可编辑变量：
- 场景：{{场景}}
- 录音时长：{{录音时长}}
- 说话人数：{{说话人数}}

请根据场景自行生成合适的录音标题、内容摘要和完整逐字稿。场景可以是会议、访谈、课堂、补课、培训、咨询、复盘、讲座或其他真实录音活动。

输出必须严格包含三个部分：

【录音标题】
生成一个准确、具体、便于检索的标题，不要使用“录音内容”“测试数据”等空泛名称。

【内容摘要】
摘要必须完整提供，不得省略，不要写“见逐字稿”。
摘要长度约为逐字稿的 10%–20%，并根据具体场景组织内容，不要强行套用会议格式。
摘要应覆盖：
1. 场景背景、参与者关系或内容目标。
2. 主要话题、知识点、问题、观点或过程。
3. 重要结论、讲解结果、共识、分歧或学习效果。
4. 后续安排、练习、建议、任务或待确认信息；没有则明确写“无”。
5. 对理解内容有帮助的关键事实、数字、术语或注意事项。
摘要必须与逐字稿一致，逐字稿未出现的事实不得写入摘要。

【录音逐字稿】
1. 所有角色只能命名为“说话人1”“说话人2”……，数量必须等于 {{说话人数}}。
2. 每段格式固定为“说话人N：发言内容”，每段之间空一行。
3. 不要生成时间戳，系统会自动生成。
4. 根据 {{录音时长}} 生成足够长度。按自然中文对话约每分钟 180–240 个汉字估算；例如 10 分钟约 1800–2400 字，20 分钟约 3600–4800 字，30 分钟约 5400–7200 字。
5. 每位说话人至少出现 3 次；两人场景应保持多轮往返，不能变成单人长篇报告。
6. 内容必须符合真实录音转写特征，适量出现“嗯、呃、对、就是、然后、那个”等口语词，以及少量重复、自我纠正、停顿、插话、确认和不同意见。
7. 口语特征控制在约 10%–20% 的发言中，不要每句话都加入语气词，也不要故意制造大量错别字。
8. 不同说话人的表达方式应有差异；身份只能通过内容自然体现，名称仍必须使用“说话人N”。
9. 对话中必须实际出现摘要里的关键内容、结论和后续安排，确保摘要可以从逐字稿中溯源。
10. 不要输出 Markdown 代码块，不要解释生成过程，不要出现“作为 AI”等说明。
```
